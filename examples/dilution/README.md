# Fresh-source end-to-end example

**Observed boundary:** normal stage-five builds did not autonomously complete acceptance.
A planner-generated strict integer predicate conflicted with source-proven float
results. A later **explicit source-backed correction**, real independent model review,
contract v2→v3 and 13 real Docker checks qualified the unchanged delivery. This was not
an automatic oracle-repair loop and did not change business code or broaden assertions.
The [base-counting example](../base-count/README.md) is a separate creation experiment.

The input is newly written source software and a documented ideal-dilution contract,
not a prepared Skill. `resources/dilution.py` release 1.0 uses Python 3.11's standard
library. Model discovery, authored instructions, independent review, environment
plan and locked tests must be generated by the normal pipeline.

From the repository root, using an existing Python environment with jsonschema,
authenticated Codex CLI and a Linux/amd64 Docker engine:

```sh
python -m creation_pipeline build examples/dilution/input.json --state-dir .pipeline/dilution --library-dir ./dilution-library --keep-debug
python -m creation_pipeline library ./dilution-library
python -m creation_pipeline library ./dilution-library --include-candidates
```

Use the actual discovered candidate name in these commands; model runs need not
choose identical names or bytes:

```sh
python -m creation_pipeline install ./dilution-library --name ideal-dilution-calculator --destination ./installed
python -m creation_pipeline runtime-inspect ./dilution-library --candidate ideal-dilution-calculator
python -m creation_pipeline runtime-resume ./dilution-library --candidate ideal-dilution-calculator
python -m creation_pipeline runtime-build ./dilution-library --candidate ideal-dilution-calculator
python -m creation_pipeline runtime-relocate ./moved-library --candidate ideal-dilution-calculator --revalidate
```

Copy or ZIP the **whole library**, including catalog, frozen evidence and dynamic
runtime records, before the last command. Moving a library does not preserve its
current execution qualification. No old project directory is required. Frozen
input hashes, exact image identity and locked assertions are rechecked.

`--draft-only` creates nonqualified drafts. A missing Docker engine produces a
persisted blocker, not an execution pass. Restore resources and use runtime-resume;
do not manually edit frozen files. Content fixes require authorship and independent
review; environment-only recovery cannot clear revoked content.

The fixed source examples expect 10 mL stock + 40 mL diluent, and 12 + 0 for equal
concentrations. This is an ideal arithmetic model, not a wet-lab safety protocol or
general scientific-validation claim. Evidence and actual coverage are recorded in
`docs/integration/stage-five.md`; running this recipe is not itself proof of success.

To reproduce the explicit correction from the preserved failed native output in a
fresh library (not to simulate a fresh automatic build):

```sh
python -m creation_pipeline runtime-import validation/stage5/interrupted-third-output ./oracle-reproduction --candidate ideal-dilution-calculator
python -m creation_pipeline runtime-prepare ./oracle-reproduction --candidate ideal-dilution-calculator --spec validation/stage5/oracle-spec.json --oracle-correction validation/stage5/oracle-correction.json
python -m creation_pipeline library ./oracle-reproduction
```

Import intentionally returns `not_run` (exit 1). The correction specifies exactly three
singleton numeric-type predicates justified by `type=float`, batch `float()`, true
division and subtraction in the original source. The proposal generator never reads
execution observations. Existing numerical values, exact stdout, all inputs/negative
cases/operations and authored tests are preserved. The independent reviewer can reject
it; approval is not assumed. The new revision's execution must pass before admission.
Prior contract and failed attempt remain accessible through catalog history.
