# 三条共享路径的性能与存储对照（2026-11-01）

基线 `ffa00a1`。使用前轮真实生成、独立审阅并实际验收的原子映射 Skill A 与 B。
本轮是固定合同的基础设施测量，不是新模型生成批次；不调用发现、编写、审阅或 planner 模型。
原后端配置及 build/test/total 时限保留，模型入口显式禁止调用。

每份 Skill 进行三组独立对照，每组按顺序运行：

1. 环境登记未命中、工具登记未命中：新的环境与工具登记目录，允许各一次 build。
2. 环境命中、工具登记未命中：沿用该组环境目录，选择另一个全新工具登记目录；仅工具 build。
3. 完整 ToolArtifact 命中：沿用第二步工具目录，绑定其具体版本；两类 build 均为零。

所有新目录都在新证据根内，不删除或移动现有登记、镜像及 BuildKit 缓存。
第二条路径模拟的是同一工具尚未登记的情形，并非换工具制造工作负载差异。
因此它测量精确命中状态带来的流程差别，不声称再次证明不同工具的环境兼容性。
每份 Skill 的源码、来源闭包、依赖声明、平台、资源要求、计划及整个验收 payload 完全一致；
同一组 request_key 不变，第二步和第三步的具体 artifact_id 一致。

A 的工作负载为 21 个原用例，B 为 20 个原用例，均包括原生审阅检查、业务负例及持久文件输出。
比较应在各 Skill 内进行，不把 A/B 的总耗时差异归因于共享模式。
顺序没有随机化，样本较少，结果是这台已预热主机上的描述性统计，不是冷启动或普遍加速承诺。

模型时间固定为零是因为三条路径都由调用方提供原冻结计划及原锁定验收，不能据此声称第一、
二条路径在完整生成中无需 planner。前轮真实模型证据独立列于
[验收专用阶段](shared-tool-acceptance-model-20261101.md)：成功 A 为 6 次（其中组合规划 3 次），
成功 B 为 5 次（其中验收专用规划 2 次、环境规划 0 次）。这是历史观察，未计作本轮调用，
也不能直接填充本轮中间路径的模型耗时。该路径完整模型生成耗时本轮未测。

阶段计时使用 monotonic，记录准备、冻结、build/bind、validation、全部用例、业务用例、最终
资格核验和总耗时；单独记录实际环境/工具 build 命令耗时。build/bind 包括确定性身份及字节核验，
并非只包含 Docker build。嵌套阶段不相加为总耗时。来源复制、缓存基础镜像查询和存储采样不在
计时窗口内；模型阶段没有新调用。执行时不并行运行本项目回归测试，减少人为负载干扰。

存储分为三种不相加的口径：

- Docker Engine `GET /system/df` 的未舍入字节：LayersSize、image/cache usage，逐镜像 Size、
  SharedSize 和可求得的 unique bytes，及前后 image ID 集合。API 的未知/负数不转换成 0。
  镜像虚拟大小不求和；build cache 与 image layers 可能共用数据，也不相加。
- Docker Desktop 数据文件系统 `df -B1 /mnt/docker-desktop-disk` 的 used bytes。它包含其他
  镜像、容器、缓存、日志和元数据，差值不能全部归因于本实验，也不是 Windows VHD 文件的物理分配量。
- 本实验 run 与登记 JSON 文件的逻辑字节数（文件长度之和）。这是交付/证据成本，不当作 NTFS
  分配字节或 Docker 镜像占用。采样文件独立保存在计时目录外。

Engine 查询与文件系统查询依次进行，并非原子快照；保留采样时刻及采样耗时。没有把两种
统计合并为单个占用值，也没有清理主机现有容器、镜像或缓存。

Docker 官方区分 shared size、unique size 和 virtual size；本报告保留这些不同概念，
不以镜像 Size 求和推算实际节省。[Docker system df 文档](https://docs.docker.com/reference/cli/docker/system/df/)
与 [Engine API](https://docs.docker.com/reference/api/engine/version/v1.52/) 是字段口径依据；测量结果来自本机。

每个阶段保留完整脱敏 build 命令输出和 `CACHED` 行。环境登记 miss 只意味着进入构建流程，
不意味着 pip 安装实际执行；build 调用数也不等于安装执行次数。基础镜像已存在，所有 Docker/
BuildKit 缓存均保留；后续组受到此前运行的进一步预热影响。

脚本 `validation/deepseek-api/measure_shared_tool_paths.py <fresh-root>` 默认每份 Skill 三组，
`--repetitions` 支持 1–3 组；`--offline` 运行两份真实材料的完整准备校验且禁止 Docker/模型调用。
Engine 精确字节采样器目前仅支持当前本机 Windows named pipe，子进程限时 60 秒；不支持的
endpoint 明确报错，不悄悄改成舍入值。pipe 采用缓冲读取，离线测试覆盖分段/chunked 响应。

第一测量目录 `shared-paths-measurement-20261101-01` 在业务执行前因脚本状态处理错误退出：
冻结记录为 not_run，重新 finalize 丢弃了有效内容状态，且旧 runtime_preparation 掩盖了 prepare
未执行。诊断保留于该目录，0 模型、0 build、0 业务执行。修复保留原内容绑定、显式撤销执行资格、
删除过期准备状态并要求非空准备材料；完整离线准备确认新验收 payload 与原合同逐字段一致。
失败轮未恢复或重启；正式测量使用独立新目录。
