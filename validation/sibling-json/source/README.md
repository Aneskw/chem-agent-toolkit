# Source tool: descriptor rule screening
This new integration sample combines the unchanged original RDKit descriptor module with a new operational screening entry and a bundled JSON rule. No chemistry output is fabricated. The original source module and requirements are copied byte-for-byte from chem-rdkit-descriptors; do not edit them.
Interface: python scripts/screen.py --smiles VALUE. --help exits 0. One JSON object on stdout; valid SMILES exit 0, invalid or empty exit 2. No file-input or output-file interface is claimed for this new entry.
Pinned dependencies: rdkit==2024.9.6 numpy==1.26.4 pillow==11.3.0. Python 3.11, CPU-only, no downloaded weights or services; resource peak is unmeasured for arbitrary molecules. Bounded acceptance uses small molecules only.
Keep all original descriptor fields, input and canonical_smiles. CCO has molecular_weight 46.069, h_bond_donors 1 and h_bond_acceptors 1; policy maximum 50.0 means selected true. Phenol c1ccccc1O has weight 94.113 and selected false. Rules are operational choices, not a chemical safety or druglikeness standard. The fixed data identity must be observed, not inferred from package prose.
Both invalid not-a-smiles and empty string must emit ok:false and error "Invalid or empty SMILES", exit 2. Test help, both valid selection branches and both rejection cases; assert persisted rule policy_id and maximum in actual JSON results. Checks must invoke the delivered entry inside Docker, retain original modules/data bytes and never use execution output as its own oracle.

This is a new isolated sample assembly. The screening wrapper uses exactly Path(__file__).with_name("rules.json").read_text(encoding="utf-8") for the sibling scripts/rules.json resource. The original calc_descriptors.py, pinned requirements.txt and rules.json bytes are unchanged; no original source is edited. This adds no dynamic loader, external process or remote resource.
